# Tier 3 - Persistence

The data: tables, database changes, the second (FreeRADIUS) database and encryption of stored secrets.

**Rule:** this tier depends on nothing above it (no `application.*` or `presentation.*` imports).
`python manage.py check_architecture` enforces this.

Each area here is a Django app. Its **label** (`devices`, `backups`, `radius` ...) is fixed in `apps.py`,
so table names and the migration history stay the same whatever folder the code is in.

## Folders

| Folder | Files | Tables / job | Database |
|---|---|---|---|
| `core/` | `crypto.py`, `keys.py` | Fernet encryption of device passwords; key files in `data/` | - |
| `accounts/` | `models.py`, `admin.py`, `apps.py` | `User` (portal users, `Role`) | `dbms` |
| `devices/` | `models.py`, `admin.py`, `apps.py` | `Device` (passwords encrypted with `core/crypto.py`) | `dbms` |
| `backups/` | `models.py`, `admin.py`, `apps.py` | `BackupLog`, `BackupJob`, `AuditEvent` | `dbms` |
| `monitoring/` | `models.py`, `admin.py`, `apps.py` | `PingHistory` | `dbms` |
| `scheduling/` | `models.py`, `admin.py`, `apps.py` | `AppSetting` (settings, key / value) | `dbms` |
| `commandlog/` | `models.py`, `apps.py` | `CommandEvent`, `SyslogSource`, `ReceiverState` (Session Log) | `dbms` |
| `radius/` | `models.py`, `apps.py` | FreeRADIUS tables `radcheck`, `radusergroup`, `radgroupreply`, `nas`, `radpostauth`; panel tables `dbms_user_nas`, `dbms_user_grant`, `dbms_nas_role`; `AuditLog` | `radius` |
| | `router.py` | Sends the RADIUS tables to the `radius` database | |

Every area also has `migrations/`: database changes generated by Django. Do not edit or delete them.

## Changing a table

```bash
# 1. change persistence/<area>/models.py
python manage.py makemigrations <area>      # 2. writes persistence/<area>/migrations/00xx_....py
python manage.py migrate                    # 3. applies it (deploy/install.sh does this on a server)
```

Backup files, keys and settings that are not tables live in the `data/` folder on the server (not in Git).
